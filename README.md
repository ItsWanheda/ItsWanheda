## 01 · Profile

I'm interested in what happens **beneath the surface of software and networks**: how systems are designed, how components communicate, where failures emerge, and how applications can be made more secure and reliable.

My work and learning connect four areas:

| Focus | What I explore |
| --- | --- |
| 🔐 **Cybersecurity** | Security analysis, defensive tooling, web security, and threat behavior in controlled, authorized environments |
| ⚙️ **Backend engineering** | APIs, authentication, application architecture, validation, and data-driven services |
| 🌐 **Networking & systems** | Protocols, traffic behavior, operating systems, and practical network utilities |
| 🛠️ **Developer tooling** | Automation and focused tools that make technical work easier |

> **Understand the system. Find the weakness. Build the defense.**

I learn by building, testing, debugging, documenting, and iterating on practical projects.

## 05 · Currently Exploring

- **Defensive security** — translating security concepts into practical analysis and defensive tooling.
- **Network behavior** — understanding protocols, traffic, and communication between services.

- **Secure architecture** — strengthening validation, authentication, configuration, and failure handling.

## 06 · Engineering Principles

| Principle | How it shapes my work |
| --- | --- |
| **Understand before optimizing** | Study system behavior before changing it. |
| **Secure by design** | Treat validation, permissions, and failure paths as core features. |
| **Prefer useful simplicity** | Build focused tools with clear responsibilities. |
| **Test and document** | Make behavior reproducible and easier for others to understand. |
| **Keep improving** | Treat debugging and feedback as part of the development process. |
